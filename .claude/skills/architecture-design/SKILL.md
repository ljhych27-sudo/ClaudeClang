# 아키텍처 설계 (A-SPICE SWE.2)

## 산출물
| 파일 | 내용 |
|---|---|
| `docs/architecture/software_architecture.md` | 컴포넌트, 인터페이스, 정적·동적 뷰, 설계 결정 |
| `docs/traceability.md` | 요구사항 ↔ 컴포넌트 열 갱신 |

## 필수 규칙
1. **모든 컴포넌트(CMP)는 인터페이스(CIF)를 반드시 하나 이상 정의한다.** 인터페이스 없는 컴포넌트는 허용하지 않는다.
2. **컴포넌트 간 연결은 오직 인터페이스를 통해서만** 한다. 다른 컴포넌트의 내부 헤더·전역 변수·구조체 멤버에 직접 접근하는 설계는 금지한다.
3. **고응집·저결합**: 하나의 컴포넌트는 하나의 책임 영역만 갖는다. 컴포넌트 간 의존은 단방향이며 순환 의존을 금지한다.
4. **모듈화·캡슐화**: 컴포넌트 내부 데이터는 외부에 노출하지 않는다(불투명 타입·접근 함수 사용).
5. **SOLID** 적용 기준:
   | 원칙 | 아키텍처 수준 적용 |
   |---|---|
   | SRP | 컴포넌트당 하나의 변경 이유 |
   | OCP | 새 기능은 인터페이스 구현 추가로 확장, 기존 컴포넌트 수정 최소화 |
   | LSP | 같은 인터페이스의 구현체는 계약(사전·사후 조건)을 동일하게 만족 |
   | ISP | 사용자별로 작은 인터페이스로 분리, 쓰지 않는 함수에 의존하지 않음 |
   | DIP | 상위 컴포넌트는 하위 구현이 아닌 인터페이스에 의존 (C: 함수 포인터 테이블/링크 시점 주입) |

## 절차
1. `docs/requirements/`의 요구사항을 읽고, 모든 SWR/SSR을 최소 하나의 컴포넌트에 할당한다.
2. 컴포넌트를 식별·정의한다 (아래 템플릿).
3. 각 컴포넌트의 인터페이스를 정의한다 (아래 템플릿). 데이터 타입, 범위, 단위, 에러 반환값, 호출 맥락(동기/비동기, 재진입성)을 빠짐없이 적는다.
4. **정적 뷰**: 컴포넌트 다이어그램(Mermaid)으로 컴포넌트와 인터페이스 연결을 그린다. 화살표는 반드시 CIF를 거친다.
5. **동적 뷰**: 주요 시나리오별 시퀀스 다이어그램, 필요 시 상태 다이어그램을 그린다.
6. **자원 소모 목표**: 제한 요구(SWR-L)를 컴포넌트별 예산(메모리, 실행 시간)으로 배분한다.
7. **설계 결정 기록**: 대안과 선택 이유를 `Design Decisions` 절에 남긴다.
8. 추적성 매트릭스를 갱신하고 `aspice-reviewer` 서브에이전트(`review` 스킬)로 아키텍처 리뷰를 수행한다.

## 컴포넌트 템플릿
```markdown
### CMP-001 <컴포넌트 이름>
- Responsibility: <단일 책임 한 문장>
- Traces: SWR-F-001, SWR-Q-002
- Provides: CIF-001, CIF-002
- Requires: CIF-007 (CMP-003 제공)
- Resource budget: RAM <n> B, ROM <n> B, WCET <n> us
- Safety: None | ASIL-x (SSR-NNN)
```

## 인터페이스 템플릿
```markdown
### CIF-001 <인터페이스 이름>
- Provider: CMP-001 / Consumers: CMP-002
- Type: Function call | Callback | Shared data via accessor | Message
- Operations:
  | 함수 | 파라미터(이름: 타입, 범위, 단위) | 반환값 | 사전 조건 | 사후 조건 |
  |---|---|---|---|---|
- Error handling: <반환 상태 코드와 의미>
- Timing / Reentrancy: <호출 주기, 동기·비동기, 재진입 가능 여부>
```

## 금지 패턴
- 컴포넌트 간 전역 변수 공유, 다른 컴포넌트 내부 헤더 include
- 순환 의존 (A→B→A)
- "Utils", "Common", "Manager" 같은 책임 불명확 컴포넌트
