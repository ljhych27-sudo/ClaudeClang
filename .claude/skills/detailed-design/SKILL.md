# 상세 설계 (A-SPICE SWE.3 — Detailed Design)

## 산출물
| 파일 | 내용 |
|---|---|
| `docs/design/<CMP-ID>_<이름>.md` | 컴포넌트별 모듈 상세 설계 |
| `docs/traceability.md` | 컴포넌트/요구사항 ↔ 모듈 열 갱신 |

## 인터페이스 정의 의무 기준
다음 중 **하나라도 해당하는 모듈(MOD)은 인터페이스(MIF)를 반드시 정의**한다.
- 다른 모듈 또는 다른 컴포넌트에서 호출되는 모듈 (공개 함수가 있는 모듈)
- 상태 또는 데이터를 소유하는 모듈
- 기능안전 요구(SSR)에 할당된 모듈
- 단위 테스트의 독립 대상이 되는 모듈

이 기준에 해당하지 않는 모듈(파일 내부 `static` 헬퍼 등)만 인터페이스 정의를 생략할 수 있으며, 생략 사유를 적는다.

## 필수 규칙
1. **인터페이스가 정의된 모듈은 오직 그 인터페이스(MIF)로만 통신한다.** 다른 모듈의 `static`이 아닌 내부 심볼, 내부 구조체 멤버에 접근하지 않는다.
2. **단일 책임 원칙(SRP)**: 모듈 하나는 하나의 변경 이유만 갖는다. 설명에 "그리고"가 필요하면 분리를 검토한다.
3. **클린코드 원칙**을 설계 단계에서 반영한다.
   - 의도를 드러내는 이름 (모듈·함수·변수)
   - 함수는 한 가지 일만 하고 짧게 (목표: 40줄 이하, 순환 복잡도 10 이하)
   - 파라미터는 3개 이하 (초과 시 구조체로 묶음)
   - 부수 효과를 숨기지 않음, 명령과 조회 분리
   - 매직 넘버 금지 → 이름 있는 상수
   - 중복 금지 (DRY)
4. 모든 함수는 `implementation` 스킬 규칙(상태값 반환, 단일 return)을 만족하도록 설계한다.

## 절차
1. 상위 컴포넌트(CMP)와 할당된 요구사항을 확인한다.
2. 컴포넌트를 모듈로 분해하고 각 모듈의 책임을 정의한다.
3. 기준에 해당하는 모듈의 인터페이스(MIF)를 정의한다.
4. 모듈별 동적 동작을 기술한다: 처리 흐름(의사코드 또는 플로차트), 상태 머신, 에러 처리 경로.
5. 데이터 정의: 타입, 범위, 단위, 초기값, 소유 모듈.
6. 추적성 매트릭스를 갱신하고 `review` 스킬로 상세 설계 리뷰를 수행한다.

## 모듈 템플릿
```markdown
### MOD-001 <모듈 이름>
- Component: CMP-001
- Responsibility: <단일 책임 한 문장>
- Traces: SWR-F-001, CIF-001
- Files: src/<comp>/<module>.c, include/<comp>/<module>.h
- Interface: MIF-001 | 생략 (사유: 내부 static 헬퍼)
- Data: | 이름 | 타입 | 범위 | 단위 | 초기값 |
- Behavior: <의사코드 / 상태 머신 / 시퀀스>
- Error handling: <발생 가능한 오류와 반환 상태>

### MIF-001 <인터페이스 이름>
| 함수 시그니처 | 설명 | 파라미터 범위 | 반환 상태 | 사전/사후 조건 |
|---|---|---|---|---|
```
